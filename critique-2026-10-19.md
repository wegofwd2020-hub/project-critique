## RESOLVED — items previously flagged that are now closed

### ✅ [P1 CLOSED] Platform deployed to production VPS

The headline gap from v1.8/v1.9 — "the platform has never run outside Docker-on-localhost" — is resolved.

The platform now runs on a Hetzner VPS (`77.42.13.139` / `demo.usestudybuddy.com`). The stack:
- CI/CD via `.github/workflows/deploy-demo.yml` — auto-deploy on merge to `main`; builds `api` + `web` images, pushes to GHCR, SSHs to VPS, runs smoke checks against the live domain, and opens a `incident:demo` GitHub issue on smoke failure.
- TLS: Cloudflare → host nginx (Origin Cert, port 443) → loopback 8443 → Docker nginx (plain HTTP). Certificates handled by Cloudflare; TLS not terminated inside the container.
- Production compose: `deploy/studybuddy/overrides.yml`. PgBouncer dropped (demo scale), `celery-pipeline` and `celery-beat-standby` disabled, `restart: always` on all services, named volumes for data persistence, `autoheal` container restarts wedged `api` within ~90 s.
- Multiple fix commits hardened the deploy workflow itself (env-file race, GHCR tag propagation lag, disk space, sudo permissions, token passing).

**Caveat — Epic 2 doc not updated.** `docs/epics/EPIC_02_production_launch.md` still reads `G-1: ⏸ Blocked — hosting decision pending`. The deployment happened; the doc did not follow. New P3: update the epic and mark G-1 done.

## NEW GAPS — issues introduced since v1.9

### ❌ [Security — NEW P1] Swagger/ReDoc live on deployed demo server

`deploy/studybuddy/overrides.yml` sets `APP_ENV: staging`. The Swagger gate in `app_factory.py:365` checks `settings.APP_ENV != "production"` — so `/api/docs` and `/api/redoc` are publicly accessible on `demo.usestudybuddy.com`. The gate worked correctly when the platform was local-only (the risk was theoretical); with a live internet-facing server, it is a real exposure. Fix: change the overrides to `APP_ENV: production`, or widen the gate to `in {"production", "staging"}`.

This also means the long-standing "APP_ENV enum assertion" gap (no `Literal["development","staging","production"]` in `config.py`) is now urgent: the deploy silently accepted `staging` as a valid value, but nothing prevents a typo (e.g., `APP_ENV: prod`) from silently keeping docs exposed.

### ⚠️ [Security — NEW P2] Missing security headers in deployed nginx

`scripts/demo/nginx.conf` adds only `X-Content-Type-Options nosniff` and `Referrer-Policy strict-origin-when-cross-origin`. Missing for a minor-facing platform:
- No `Content-Security-Policy` (XSS vector; CSP was flagged as a requirement in v1.8 §5 and has not been addressed)
- No `Strict-Transport-Security` (HSTS — Cloudflare handles TLS but no HSTS header is forwarded from the origin)
- No `X-Frame-Options` (clickjacking)
- No `Permissions-Policy`

These belong in the nginx `add_header` block before the first real-school pilot.

### ⚠️ [Security — NEW P2] python-jose CVE-2026-85394 (algorithm confusion) on live server

`ci: unblock main lint (auth0 typing + python-jose CVE ignore)` (`fe8b711`, 2026-10-11) added a new pip-audit ignore for `CVE-2026-85394` (algorithm confusion in python-jose 3.5.0 — latest PyPI release). The ignore comment is honest and well-reasoned: verifiers pin algorithms (`RS256` for Auth0, symmetric secrets for internal tokens), so the public-key-as-HMAC confusion path is not reachable. However:
- The CVE is live on a deployed server.
- The upstream fix exists but is unreleased.
- No ticket or scheduled review was created to remove the ignore once a fixed release ships.

Add a GitHub issue to track the unignore; set a calendar reminder or dependabot pin bump.

### ⚠️ [NEW P2] `purge_account.py` safety gap now material

This was a P2 in v1.8 (comment-only gate, no `APP_ENV`/hostname assertion). With the platform live on `demo.usestudybuddy.com`, the gap is now material: the script could be run against the demo database with real demo-school data. Priority escalated.
