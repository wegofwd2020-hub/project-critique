## Resolved since v2.3

### ✅ RESOLVED — Admin audit log endpoint built (#606, part of #604)

`GET /admin/audit` was listed in KNOWN_BROKEN and returned 404 on every load, so the Audit Log page linked from the admin nav has never shown data. The table carries 229 real rows on the demo. Endpoint now implemented: newest-first, page/page_size, optional action filter, gated on new `audit:view` permission granted to product_admin and above. Two real-data corrections: 218 of 229 rows have NULL target (logins have no resource), so `resource_type`/`resource_id` are nullable; asyncpg returns JSONB as string without a codec, now decoded before validation. 8 new tests (all failed first with 404).

### ✅ RESOLVED — Feedback resolve endpoint built (#607, part of #604)

`POST /admin/feedback/{id}/resolve` had never existed despite the "Resolve" button shipping in the admin Feedback page since it was built. Clicks 404'd and went unnoticed because the feedback table was empty (#600). Endpoint is idempotent (first reviewer wins; double-click safe), gated on new `feedback:resolve` permission (product_admin+). 7 new tests.

### ✅ RESOLVED — Subscription analytics URL typo fixed (#608, part of #604)

The admin dashboard and analytics page both called `/admin/analytics/subscriptions` (plural); the API serves `/admin/analytics/subscription` (singular). One-character mismatch meant both pages showed nothing. Bonus: the TypeScript type promised `active_monthly`/`active_annual` fields that do not exist anywhere in the schema; those are now replaced with the real `by_plan` breakdown (starter/professional/enterprise). MRR computed from `_PLAN_PRICE_USD` constants against active rows. Both screens now show real data.

### ✅ RESOLVED — Dead ADR-001 subscription client code purged (#610, part of #604)

Individual student subscriptions (dropped in migration 0027) and the private teacher tier (dropped in migration 0026) still had live client functions calling 404 endpoints. `TrialBanner` was rendering null (invisible) but firing a failing request on every student page load. All deleted: `TrialBanner`, `useSubscription`, `lib/api/subscription`, `/account/subscription/success` (Stripe return page for a checkout that cannot happen), the admin private-teacher nav item and page. `/account/subscription` is kept but rewritten to explain that the school controls access instead of advertising prices of $9.99/$99.99 that no student can pay. i18n: obsolete purchase strings removed, new explanatory strings added across en/fr/es with key parity verified. KNOWN_BROKEN reduced from 4 to 2 after this + the two endpoint PRs.

### ✅ RESOLVED — Enrol-by-code endpoint built (#617, closes half of #609)

`POST /school/enrol/confirm` was in KNOWN_BROKEN: the school portal generates invite URLs (`/enrol/{code}`) and tells admins to send them to students, but the endpoint never existed — every student following one hit a 404 dead end. Now implemented with three deliberate constraints: (1) seat-limit check runs the same logic as roster upload, so invite links cannot silently exceed a school's plan; (2) a student already enrolled at another school gets 409 and stays put (school transfer is an administrative act, not a link click); (3) a wrong code returns the same 404 whether or not any school matches — no school name, id, or code in the response (test asserts this). Re-opening the link is idempotent. RLS bypassed by design (pitfall #23 pattern): the student is not yet scoped to the school they are joining; the code is the authorization. 7 new backend tests. KNOWN_BROKEN now contains only the COPPA consent endpoint (which needs a product decision, not code).

### ✅ RESOLVED — API healthcheck bounding (#599)

The API healthcheck previously had no timeout bound, so a wedge could strand processes indefinitely. Healthcheck timeout is now bounded. Companion to #621 below.

### ✅ RESOLVED — Admin dashboard silent failures surfaced (#604 family)

The v2.2 Audit, Feedback Resolve, and Subscription Analytics items were filed together as #604. All three are now closed. The KNOWN_BROKEN contract check enforces each corrected path.

## New issues introduced this window

### 🔴 NEW — API wedge root cause unknown (#620, open)

On 2026-08-21 the API wedged at 00:13 UTC: alive and accepting connections, holding zero DB connections, logging nothing. Docker had the container marked `unhealthy` for 21 hours before a QA tester noticed (13 hours after it wedged). Recovery in this incident required manual restart. The autoheal mitigator (#621, below) bounds future incidents to ~80-90s; the root cause of the wedge itself is undiagnosed. Issue #620 remains open. This is a production-readiness concern — a wedge on a production host with real students would be invisible until autoheal fired.

### ⚠️ NEW — Autoheal mounts Docker socket (demo box) (#621)

`willfarrell/autoheal` restarts the API container when Docker marks it unhealthy, using a 5s poll. The container requires `/var/run/docker.sock` which is root-equivalent on the host. Commit message is transparent about this: accepted for the demo box (everything already runs as root) because the alternative (a host-level cron) would live outside version control. The autoheal image is pinned by digest (not `:latest`) after a same-session security review flagged the supply-chain risk. **For production:** the Docker socket exposure must be revisited before this pattern is inherited. Filed as a P3 observation; if production uses the same compose overlay it becomes P2.

### ⚠️ NEW — Session expiry relies on localStorage tokens remaining (#615)

Browser-close + 30-minute idle logout is now implemented via `lib/auth/session-policy.ts` + `lib/auth/session.ts` + `SessionGuard` in student/school/admin layouts. The implementation is explicit: tokens intentionally stay in localStorage (not moved to sessionStorage) because ~40 files read them directly. A single liveness marker in sessionStorage is the "browser was closed" signal. This correctly solves the shared-machine problem (#601) without touching 40 files. The residual: JWTs remain exfiltrable from localStorage by any XSS. For a platform serving minors this is worth noting, but it is a pre-existing architectural risk, not new exposure introduced by this PR.
