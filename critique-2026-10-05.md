## Resolved Since v1.9

### ✅ LessonRenderer content-rendering regression closed (`73e70d1`)

Section bodies and key-point bullets in `LessonRenderer.tsx` were rendered as `whitespace-pre-wrap` text — bypassing the shared `SBMarkdown`/`SBMarkdownInline` pipeline and silently discarding KaTeX expressions, markdown tables, and lists. This was a functional regression against Epic 11 C-1–C-4 (the whole point of the formatted pipeline) that was invisible to the a11y-weighted E2E suite.

Fix: `section.body` now goes through `<SBMarkdown>` and each key-point bullet through `<SBMarkdownInline>`. `TutorialRenderer.tsx` received the same fix for `common_mistakes` items.

**Implication for open risk:** This confirms that the "E2E coverage is a11y-weighted" finding (§3 gap, every critique since v1.3) is not just a coverage metric concern — it allowed a content-rendering regression to accumulate undetected while the formatted-content pipeline itself was shipping. The case for expanding functional E2E coverage is now empirical, not theoretical.

### ✅ Auth0 localhost dev init hardened (`3808560`, `acfb885`, `73e70d1`)

Three compounding Auth0 dev-mode failures are now fixed:

- `web/lib/auth0.ts` skips `Auth0Client` instantiation when `AUTH0_DOMAIN` is unset or resolves to `localhost` (dev stack has no Auth0 tenant).
- `proxy.ts` returns `NextResponse.next()` instead of `undefined` on `DomainResolutionError` — middleware was silently blocking the rewrite proxy in dev mode.
- `web/app/(student)/layout.tsx` catches sync Auth0 throws via `Promise.resolve().then()` instead of bare `await`.
- `backend/config.py` defaults Auth0 fields to `""` so a `.env` predating the Auth0 section block does not cause startup failure.

These are dev-ergonomics fixes, not production security changes, but they unblock local testing of the student portal without a live Auth0 tenant.

## New Capabilities Since v1.9

### WikimediaVisual inline images (`beef1c1`)

New surface: `GET /content/visuals/wikimedia?query=<text>` proxies [Wikimedia Commons API](https://commons.wikimedia.org/w/api.php), selects the best non-animated thumbnail, and returns `{title, url, attribution}`. 24h Redis cache (`wikimedia:v1:<sha256-prefix>`). Backend schemas: `VisualHint`, `WikimediaImageResult`. Frontend: `web/components/content/WikimediaVisual.tsx` — rendered after each matching section in `LessonRenderer`.

`_visual_hints_block` in `pipeline/prompts.py` is extended to cover Chemistry, Physics, Mathematics, Geography, Political Science, and Psychology (was: Commerce, Biology, History only). All 77 authored curricula will now generate `visual_hints` fields on next regen.

**New risk to track (see below):** external Wikimedia Commons dependency added to the lesson render path.

### Pipeline content-store operational tools (`4481f81`)

Three new scripts in `pipeline/`:

- **`backup_content.py`** — `tar.gz` the content store as `{label}_{YYYY-MM-DD_HH-MM}.tgz`. Complements the DB-level backup Epic 15 delivered; this is the file-store side.
- **`restore_content.py`** — extract with per-member path-traversal validation (rejects any archive member whose `os.path.abspath(dest)` escapes the target root). Correct security hygiene for tar extraction.
- **`validate_content.py`** — checks JSON parseability, required lesson fields (`topic`, `sections`, `key_points`, `visual_hints`), required section fields (`heading`, `body`), required meta fields, and non-empty `visual_hints` for the 12 visual-hint subjects. Exits 0 on clean, 1 on errors. Supports `--curriculum-id`, `--grade`, `--stream` filters.

Together, `validate_content.py` + `backup_content.py` give an operator a pre-backup sanity gate. The restore script's path-traversal guard is the right shape for operator-run tooling.

`school-auth-redirects.spec.ts` (25 LOC) and `school-login-page.spec.ts` (17 LOC) add minimal smoke coverage for the school login surface — the smallest possible spec additions. They do not cover the onboarding wizard or Administration menu (those remain web-unit-tested only).

## New Risks Introduced

### ⚠️ Wikimedia Commons is now a third-party dependency in the lesson render path

`GET /content/visuals/wikimedia` makes outbound HTTP calls to `commons.wikimedia.org` at lesson render time. The 24h Redis cache reduces call frequency, but on a cold-cache request the render blocks on a live external API. Risks:

- **Availability**: Wikimedia Commons API has no SLA. A rate-limit or downtime event propagates to lesson render latency.
- **Content policy**: Wikimedia images are CC-licensed but not curated for age-appropriateness (Grades 5–12, COPPA context). There is no content-moderation gate on the returned image URL. A biology query for "human reproduction" could surface anatomically explicit illustrations.
- **Rate limiting**: No outbound rate-limit visible in the router code; under class-scale concurrent lesson opens, parallel Wikimedia requests could trigger IP throttling.

Mitigation needed before enabling for real students: (a) a fallback branch so a cold-cache miss degrades gracefully (lesson renders without image, not with a spinner), (b) a subject-specific term denylist or safe-search parameter, (c) outbound rate limiting on the proxy endpoint itself.

### ⚠️ No tests for the three new pipeline scripts

`backup_content.py`, `restore_content.py`, and `validate_content.py` have no corresponding test files. `restore_content.py`'s path-traversal guard and `validate_content.py`'s field-coverage logic are untested. The restore script is the higher-risk case: a wrong restore on a corrupted archive is harder to recover from than a failed validation.
