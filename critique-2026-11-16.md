## What Changed Since v1.9

This window is a **polish and authorization-correctness window** — no new migrations, no new ADRs, no new Playwright specs. All visible substantive commits are `fix(*)` or `chore(*)`. Key items:

### Curriculum Authorization Fixes (Two Bugs, Same Area, Same Window)

Two `fix(school)` PRs patched authorization gaps on the curriculum read path in quick succession:

- **#903** — `fix(school): let schools read platform curricula their classrooms hold; report avg score as percent` — the unit-status list returned 403 for any platform curriculum a school's classroom held but had not forked. Reads now follow classroom entitlement; writes keep the owner-only check.
- **#921** — `fix(school): let schools read the units of curricula they adopted` — a school with an active adoption but no classroom holding the curriculum got 403 on the unit list, showing "No units found". The read guard now accepts active adoption as sufficient; the frontend falls back to the route curriculum id.

**New risk flag:** Two authorization gaps in the fork-curriculum read path found in the same two-week window. The school-fork-curriculum model has three access paths (classroom holds it / active adoption / fork ownership) — the first two needed patches. It is not clear the third was audited proactively. Worth a targeted read-path authorization review before launch.

### Report Correctness Fixes

- **#904** — `fix(reports): report unpassed units' attempts as null, not zero` — units a student has never passed were reporting `attempts_to_pass: 0` instead of `null`, causing display artifacts (e.g. "0 attempts" vs "—").
- **#905** — `fix(reports): list weekly breakdown newest week first` — weekly breakdown lists were newest-last; reversed.

These are defects in the reports overhaul shipped in v1.9. No new risk class, but confirms the reports surface has ongoing correctness surface area.

### Demo/Account Boundary Fix

- **#906** — `fix(demo): block test run when the address already belongs to a real account` — a test-run request could proceed against an email that already belonged to a live account, creating collision risk. Now blocked at the API level.

Demo→production email collision was a live risk until this shipped. No scope expansion required, but worth noting it existed.

## New Issues This Window

### 1. School curriculum read-path authorization model needs an audit ⚠️ P2

Two adjacent authorization bugs (#903, #921) in the school curriculum read path were patched in the same window. Both were cases where a legitimate access path (classroom entitlement vs. active adoption) was not covered by the read guard. The fix correctly narrows *writes* to owner-only while expanding *reads* to cover both paths — but there is no evidence of a proactive audit across the full fork-curriculum access matrix (fork owner / active adoption / classroom holds / no relationship). Recommend a targeted authorization review of `GET /curricula/{id}/units` and sibling endpoints against all school-curriculum relationship states before launch.

### 2. CLAUDE.md migration table stops at 0071; filesystem has 0072–0074 ⚠️ P3

Migrations 0072 (`question_validations`), 0073 (`school_localization`), and 0074 (`version_mapping`) exist in `backend/alembic/versions/` and were counted in v1.9's measurement (74 total), but the CLAUDE.md migration table was not updated past 0071. The doc-audit `check_migrations_table.py` checker should have caught this — verify the checker is running (it was noted as "now fails instead of skip" in v1.9's #729, but that applied to doc-drift CI checks, not the migration table script specifically). Add the three missing rows to CLAUDE.md.
