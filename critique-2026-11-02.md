## Resolved Since v1.9

### ✅ [P1 re-framed] Epic 2 deployment is live; CI auto-deploy hardened

The v1.9 top-P1 action was "make the Epic 2 hosting/deployment call." That call was made in May 2026 (before v1.9 was written). This window hardened the CI path. The `deploy-demo.yml` auto-deploy workflow suffered a multi-commit debugging sprint (`5ac574c` through `3da84d6`, Oct 7–8): image-tag staleness bug (`#583` — compose was re-pulling the previous image because build tags weren't propagating correctly), `DEPLOY_SHA` written to `/tmp` vs `/home/deploy/`, SSH compound-session race, `GITHUB_TOKEN` git-pull auth, and `pull_policy: if_not_present` vs compose v5.6.0 behaviour. All resolved. The workflow now:
  1. Builds + pushes `api` and `web` images to GHCR tagged `:latest` and `:<short-sha>`
  2. SSHs to the VPS; `git pull`; `compose pull && up -d`
  3. Verifies running containers against the exact expected SHA (guards against stale-box false-success)
  4. Runs `scripts/demo/smoke.sh` (9-check curl suite) and opens a `incident:demo` GitHub issue on failure

The architecture gap ("no K8s/Terraform, no managed Postgres/Redis") remains an honest description of the VPS-based demo, but it is now irrelevant to the initial-deployment concern. Epic 2's remaining open items (G-4 observability dashboards, formal K8s/managed-infra staging path) belong in the P2 tier, not P1.

### ✅ New persona smoke test harness (`scripts/smoke/persona_smoke.py`)

Two commits (c9bd2e1, 045de02) add a 535 + 174 LOC on-demand persona smoke harness for the deployed environment:

- Creates a `smoketest-{run_id}` school, teacher (grades 9–12), 4 students (G9–G12), 4 classrooms with curriculum packages, then exercises super-admin / teacher / student API paths
- Tears down all fixtures (including via a new `DELETE /admin/test-schools/{school_id}` endpoint gated to super_admin with a `smoketest-` name prefix guard)
- Emits JSON + Markdown reports to `reports/smoke/` (gitignored)
- Exit code contract: 0 = all passed, 1 = checks failed (teardown ran), 2 = setup error; lesson 404s are warnings, 402/5xx are failures

This is a meaningful complement to `scripts/demo/smoke.sh` (infrastructure-level curl checks) — the persona harness actually exercises the school→teacher→student data path through the API. The `DELETE /admin/test-schools/{school_id}` endpoint's name-safety guard (only `smoketest-` schools) is a reasonable fence, though it relies on prefix convention rather than a database flag; not a production risk but worth noting.

## New Issues

### ➕ `python-jose` CVE-2026-85394 is pip-audit ignored with no re-check schedule

`fe8b711` correctly adds the CVE to the pip-audit allowlist rather than silently suppressing it, and names the upstream fix commit. However: (a) there is no re-check date or ticket to remove the ignore when the patched release lands on PyPI; (b) the vulnerability exists in a JWT library, which is a high-sensitivity surface for this platform. Recommend: add a comment with the upstream issue/PR URL and set a calendar reminder (or a `pip install --dry-run python-jose>=<fix-version>` step in CI) to revisit in ≤30 days.

### ➕ `DELETE /admin/test-schools/{school_id}` name-prefix-only guard

The new test-school teardown endpoint (`c9bd2e1`) guards against production data deletion by checking that the school name starts with `"smoketest-"`. This is a convention, not a database-enforced invariant — a school provisioned via the UI or seed scripts with a name starting with `smoketest-` would be eligible for deletion via this endpoint. In the current operator-controlled demo context this is acceptable, but the guard should be noted: before any multi-tenant production scenario, this endpoint either needs a database flag (`is_test_school BOOLEAN`) or should be removed from the production router.
