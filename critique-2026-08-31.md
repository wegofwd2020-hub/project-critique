## Resolved since v2.4

### ✅ RESOLVED — COPPA consent form removed (#609, #635)

The orphaned `/consent/page.tsx` (a form posting to `POST /auth/consent`, which returns 404) has been deleted rather than built. `submitConsent()` in `web/lib/api/auth.ts` removed. CLAUDE.md corrected in two places to state what is actually true: there is no consent flow; accounts are school-provisioned and the school is the consent authority. KNOWN_BROKEN allowlist is now **empty** — the contract check (`web/tests/unit/api-contract-paths.test.ts`) is fully enforcing with no exceptions.

### ✅ RESOLVED — Answer key leaked per question in `POST /progress/answer` (#684, #686)

`POST /progress/answer` was returning `correct_index` and `explanation` on each answer. Because re-answering a question is allowed (skip-and-return), an attacker could: answer anything → read `correct_index` from the response → answer again correctly → 100% score with no knowledge of the material. The answer response is now an acknowledgement only (`answer_id`, no verdict). The full reveal (`correct_index`, `explanation`, `your_answer`) moves to `EndSessionResponse.reveal`, served only when the session closes. This is a **security fix** for a live vulnerability on the same anti-cheat surface as #506.

### ✅ RESOLVED — Quiz set pinned per session (#567, #633, migration 0061)

`GET /content/{unit_id}/quiz` was calling `get_next_quiz_set()` — a state mutation as a side effect of a read. React Query's `refetchOnWindowFocus` would rotate the set mid-attempt whenever a student switched tabs. Migration 0061 adds `progress_sessions.quiz_set` (SMALLINT, CHECK 1–3). `POST /progress/session` now picks and pins the quiz set; `GET …/quiz` serves what the session pinned. The rotation pointer advances only on session close.

### ✅ RESOLVED — Progress status counts the lesson, not only the quiz (#675, #679, migration 0065)

`mv_student_curriculum_progress` was built FROM `progress_sessions` alone. "In Progress" meant "has an abandoned quiz attempt"; "Not Started" covered units whose lesson had been read end to end. Migration 0065 rebuilds the view to union `lesson_views` with `progress_sessions`, so "In Progress" now correctly means "reached the unit (lesson or open quiz)" and "Not Started" means genuinely untouched. Quiz figures (`attempts`, `best_score`, `best_pct`, `last_attempt_at`) remain quiz-only.

### ✅ RESOLVED — Temporary password expiry (#664, #674, migration 0064)

School-issued provisioned passwords now have a bounded lifetime. Migration 0064 adds `password_expires_at` on `teachers` and `students`. The column is stamped when a TEMPORARY password is issued (provisioning or admin reset) and cleared when the user sets their own. Existing rows backfill to NULL (no expiry, to avoid locking out already-provisioned accounts). Enforced at login only when `first_login` is TRUE. Reported by QA: a password emailed the previous day still worked indefinitely.

### ✅ RESOLVED — Feedback thumbs verdict (#600, #612, #613, migration 0062)

Migration 0062: `feedback.message` made nullable; `helpful` (verdict) and `content_type` columns added; `feedback_has_content` CHECK ensures at least one of message/rating/verdict is present. Fixes the silent error state on the feedback widget (Content Rule #5 violation), and hardcoded English copy in fr/es locale paths. The `feedback` table was empty for the life of the deployment because every thumbs submission failed its NOT NULL constraint.

### ✅ RESOLVED — Tutorial and experiment time never recorded (#569, #654, migration 0063)

Tutorial and Experiment pages never called the view-recording endpoint. Time spent in them counted as zero everywhere: student "Time spent", school admin per-unit Time column, and at-risk/struggle logic. Migration 0063 adds `tutorial_viewed` to `lesson_views`. The three content types (lesson / tutorial / experiment) are now distinguishable. Pages updated to record views.

### ✅ RESOLVED — Multi-school enrollment (#572, #631)

Students can now be enrolled at multiple schools simultaneously. A student attending a school plus an external tutor running additional courses on the same platform is the motivating case. Implementation: `school_enrolments` was already many-to-many (`UNIQUE (school_id, student_email)`); `provision_student` now attaches an existing identity instead of failing with "student already exists." No migration required. Password reset is restricted to the primary school (`students.school_id`). Content serving follows `students.school_id` (primary only, for now — dual-enrolled content switching is design decision 3, explicitly deferred).

### ✅ RESOLVED — Classroom packages additive (#651, #690, #691, #692)

A classroom can now hold multiple packages (curricula). Three commits: (1) `GET /content/{unit_id}` now searches across all packages the classroom holds, not just the first; (2) the assignment API now accepts a list rather than a single curriculum; (3) overlapping packages refused (a new package that shares units with one already on the classroom is rejected with a clear error).

### ✅ RESOLVED — Metrics: single definition each (#662, #668, #669, #672)

Three counters (quizzes completed, lessons viewed, average score) were computed inconsistently across the overview, at-risk, and class-metrics screens — different denominators, different filters. All three aligned to one definition per metric.

### ✅ RESOLVED — Report scope scoped to teacher's grades (#628)

Aggregate teacher reports were not scoped to the teacher's assigned grades. A teacher could see data for grades outside their own cohort. Corrected.

### ✅ RESOLVED — Empty states claiming "all clear" to restricted teachers (#647, #660, #661)

Two empty states ("no alerts", "all clear") were displayed even when the teacher had no visibility into the grade — they should not see "all clear", they should see nothing. Fixed. Grade-scope also applied to classrooms and class metrics.

### ✅ RESOLVED — Deploy verification (#583, #688, #689)

CI previously reported green while the box served images from nine days earlier (Compose pins `:latest`; a silent no-op pull left the old container running). Two-commit fix: (1) CI now extracts the deployed commit from the running container's `/health` endpoint over HTTP and asserts it matches the merged commit; (2) CI waits for readiness (not just the container starting) before running smoke tests. A follow-up (#689) corrected a `sudo docker` permission error in the same workflow.

### ✅ RESOLVED — Backup: retention pruning failing a succeeded backup (#636, #637)

A retention-pruning error was propagated to the backup task status, marking a fully succeeded backup as failed. Backup success and retention pruning are now independent — a pruning failure is logged and counted but does not fail the backup record.

### ✅ RESOLVED — Quiz refresh mid-attempt starts new session (#646)

A page refresh mid-quiz created a new session instead of resuming the open one. Fixed: the start-session endpoint detects an open session for `(student_id, unit_id, curriculum_id)` and returns it rather than opening a new one.

### ✅ RESOLVED — Quiz page load counted as attempt (#627)

Opening the quiz page was creating a phantom progress session, so every unit appeared "in progress" after the student viewed it. The session is now created only when the student explicitly starts the attempt.

### ✅ RESOLVED — Restore requests promised a delivery date (#589, #629)

Restore request confirmation messages promised a date that no code was going to honour. Message corrected.

### ✅ RESOLVED — Public site dead links (#663, #671)

Missing `/demo` page added. Two additional dead public-site links repaired.

### ✅ RESOLVED — vm-localhost-bootstrap.sh: Postgres/Redis passwords now random

DB and Redis passwords in the demo bootstrap now generated via `openssl rand -hex 32` rather than static defaults. The `DevAdmin1234!` credential still appears in a documentation comment on line 829 (the school admin account for the seeded dev school), which is in scope to rename but is a dev/demo surface, not a production credential.

### ✅ RESOLVED — ADR-007 academic calendar documented (#641)

`docs/ADR_007_academic_calendar.md` (Proposed, 2026-08-25) documents what needs to be built: term dates, enrolment windows with start/end, grade promotion with outcomes-gating, per-school grading scales (pass mark is NOT universally 60%), and a year-start freeze with a correction path. ## New issues introduced this window

### 🔴 NEW — Answer key was live on production before patch (#684, now fixed)

Noted for the record: the answer-key vulnerability (see RESOLVED above) was present in production during the window before #686 landed. It is closed, but the presence of two exploitable anti-cheat regressions (#506, now #684) within 3 months suggests the server-grading path has insufficient coverage at the integration level. The quiz-suite live harness covers the journeys but not this specific shape of response-body leak. One new test class was added (`test_answer_response_no_key`); the broader gap is that answer-API security properties are not asserted in a dedicated suite.

### ⚠️ NEW — Dual-enrolled student sees primary school content only; switcher unbuilt (#572 partial)

Multi-school enrollment shipped. Content routing follows `students.school_id` (primary). A student enrolled at two schools who needs to access the second school's curriculum cannot — there is no context-switch mechanism. Design decision 3 was explicitly deferred with the note "revisit when a tutor actually needs to deliver content." This is a known partial: it closes the provisioning bug, not the content-access gap.

### ⚠️ NEW — Academic calendar unimplemented; ADR-007 is aspirational only

ADR-007 documents a fully specified academic calendar (term dates, enrolment windows, grading scales, promotion gating) that does not exist in the schema or code. `GRADE_PROMOTION_DATE` in `config.py` is unset. `grep ACADEMIC_YEAR_START backend/` returns nothing. Until this ships: grade promotion is manual, enrolment windows are unbounded, and pass marks are hardcoded rather than per-school. No blocking issue yet; it becomes one when a school's calendar diverges from the defaults.

### ⚠️ NEW — Public marketing research investment visible (#693–#698)

Kolibri competitive analysis (`docs/COMPETITIVE_kolibri.md`), a design teardown (`docs/DESIGN_kolibri_site_teardown.md`), a public audience map (`docs/DESIGN_public_audience_map.md`), and four public-site design iterations shipped in a single week.
