## Resolved since v2.2

### ✅ RESOLVED — Admin dashboard / student stats reporting period mismatch (#573, merged 2026-08-14)

The school-admin overview dashboard was hardcoded to a hidden `period="7d"` with no selector and no period label. The student stats page (`/stats`) defaulted to `"30d"` with a working period selector. Both pages displayed metrics named "Lessons viewed" and "Quiz attempts" but used different time windows, so the numbers could differ by up to 4× with nothing on screen explaining why. A QA tester reported this as broken data (the two screens in fact agreed exactly at matching windows).

**Fix.** The admin overview KPI card group now has the same period-selector control as `/stats`, defaulting to `"30d"`. The active window is labelled on both screens. The `queryKey` now carries the actual selected period instead of the hardcoded `"7d"` literal, so changing the selector triggers a real refetch.

**Boundary decision.** The admin endpoint (`GET /school/reports/overview`) accepts `7d`/`30d`/`term`; the student stats endpoint accepts `7d`/`30d`/`all`. The vocabularies genuinely differ. The admin selector was constrained to `{7d, 30d, term}` (what its endpoint supports) rather than inventing values the backend would reject. The shared `"7d"`/`"30d"` values now mean the same window on both screens; `"term"` and `"all"` have no cross-screen equivalent.

**Scope.** The fix applies to the overview KPI card group only; the alerts, library, teachers, and class-metrics sections of the admin dashboard are unaffected and labelled as such.
