### Auth: Deleted Teacher Accounts Now Skipped (Two PRs, Same Day)

- **#923** — `fix(auth): skip retired teachers in local login lookup` — `login_local_user` teacher branch now has `AND account_status <> 'deleted'` at the SQL level. Previously a teacher with `account_status='deleted'` would be fetched and then rejected at the application level (line 488: `if row["account_status"] == "deleted": raise 401`), but only after the full lookup and capabilities load.
- **#924** — `fix(auth): skip retired teachers in password reset lookup` — `find_local_user_by_email` teacher branch gains the same guard. Without this, a forgot-password request for a deleted teacher's email would generate and dispatch a valid reset token + email.

Both PRs shipped same-day (2026-11-23). The pattern is the same: a SQL-level exclusion added reactively where application-level fallback existed. See **New Issues** for the gap this reveals.

`web/app/(school)/school/reports/trends/page.tsx` — column header renamed from "Quizzes" to "Quiz attempts". The commit message explains why: the weekly breakdown count includes **unfinished** quiz sessions, so it reads higher than the completed-quiz count a teacher sees on the student progress history. "Quiz attempts" is accurate; "Quizzes" implied completed. E2E data file (`web/tests/e2e/data/trends-report-page.ts`) updated in the same PR, keeping the Playwright fixture in sync.

## New Issues This Window

### 1. Deleted-student SQL guard missing from forgot-password and local-login paths ⚠️ P2

The two auth PRs (#923/#924) added `AND account_status <> 'deleted'` at the SQL level for the **teacher** lookup branches in `login_local_user` and `find_local_user_by_email`. The corresponding **student** lookup branches in both functions were not updated:

- `login_local_user` student branch (`backend/src/auth/service.py:424`): `WHERE email = $1 AND auth_provider = 'local'` — no deleted filter. This path is covered by application-level guard (line 488: `if row["account_status"] == "deleted": raise 401`), so login is blocked, but the account is still fetched and capabilities are loaded first.
- `find_local_user_by_email` student branch (`service.py:523`): `WHERE email = $1 AND auth_provider = 'local'` — no deleted filter. This is used by the forgot-password flow (`auth/router.py:435`). If a deleted student's email is submitted, the lookup succeeds, a valid reset token is generated, stored in Redis, and a reset-link email is dispatched. The student cannot ultimately log in (application-level 401), but a live reset token exists in Redis for the duration of `_RESET_TOKEN_TTL` and an email was sent to what is meant to be a closed account.

This is a narrow consistency gap, not a privilege-escalation risk, but it is the same class of bug as #923/#924 and was left unfinished. Recommend adding `AND account_status <> 'deleted'` to both student branches in the same style as the teacher fixes.

### 2. Auth-path deleted-status coverage is now inconsistent ⚠️ P2

The Auth0 exchange path for teachers (`service.py:327`): `FROM teachers WHERE external_auth_id = $1` — no `account_status <> 'deleted'` filter. Auth0-registered teachers who are deleted in the platform DB can still exchange a valid Auth0 JWT for a platform session token (application-level guard at line 488 blocks the final 200, but the row is fetched and processed). Recommend applying the same guard here for consistency and to avoid unnecessary DB and capability-load work on deleted accounts.
