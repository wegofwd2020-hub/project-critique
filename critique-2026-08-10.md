## Resolved since v2.1

### ✅ RESOLVED — api/web host ports exposed on `0.0.0.0` on demo server (#543, 2026-08-09)

**Was effectively P0.** `docker-compose.demo.yml` declared `ports: []` for `api` and `web` with comments saying nginx fronts everything. The override was silently a no-op: Compose *merges* port sequences, so an empty list appended nothing and the base compose's `8000:8000` / `3000:3000` survived. Docker writes its own `iptables` DOCKER chain evaluated before `ufw`, so the host firewall's 22/80/443-only policy did not apply. Both ports were publicly reachable on the origin IP, bypassing nginx, TLS, and Cloudflare, and exposing the origin address behind the proxied DNS record.

Fixed with the `!override` tag (same mechanism already used for `depends_on` in the same file). Verified: curl to origin:8000/3000 now times out; demo.usestudybuddy.com still 200.

**Residual:** `db` (line 46) and `redis` (line 54) have the same `ports: []` no-op wart. They are loopback-bound (127.0.0.1), so the exposure is contained to the host, but fixing them requires a DB restart — tracked as a follow-up. New P3 item below.

### ✅ RESOLVED — backup_cron column stored but completely ignored (#542, 2026-08-05)

Schools could set a custom `backup_cron` value in the DB, but the Celery Beat entry always fired every school at 02:30 UTC regardless. Now the coordinator runs hourly and dispatches only schools whose cron fired in the last hour. `croniter` added as a dependency; malformed crons skipped (logged), not fatal. The prior column-default/Beat-time mismatch (02:00 vs 02:30) is resolved by honouring the value.

**Remaining follow-up (new P3):** No school-facing UI for editing `backup_cron` — still admin-managed via the backup router only.

### ✅ RESOLVED — Quiz grading/serving path drift for fork-adopting schools (#538, 2026-08-05)

The serving path applied a fork→OOB source swap and checked for teacher overrides; the grading path did not. For any school that adopted a forked curriculum, every quiz answer returned `quiz_not_found` (404). Overridden quizzes graded against the store file, silently wrong (pitfall #35 — same `q1…qN` ids across bodies). Fixed by factoring shared resolution into `content/service.py::resolve_content_curriculum` and `resolve_quiz_answer_key`, used by both paths. 6 new unit tests cover the resolution order.

**Remaining follow-up:** The quiz-suite live harness does not yet have a fork/override fixture — only unit-tested. New P2 item below.

### ✅ RESOLVED — Unit rows duplicated in teacher reports (#533, 2026-08-04)

Four reporting queries grouped on `(unit_id, subject)` instead of `unit_id` alone. Because `progress_sessions.subject` stores the raw value at session time (pre-#524 sessions store `"unknown"`; post-#524 store the real code), a unit with sessions under two raw values produced two SQL rows — visible to teachers as the same unit listed twice. Fixed in `reports/service.py::get_student_report`, `get_curriculum_health` and `analytics/service.py::get_student_metrics`, `get_class_metrics`.

### ✅ RESOLVED — E2E CI Student Flow job always timed out at webServer startup (#536, 2026-08-05)

The Playwright CI job booted Next.js dev server with `@auth0/nextjs-auth0` v3 env var names (`AUTH0_ISSUER_BASE_URL`, `AUTH0_BASE_URL`). v4 reads `AUTH0_DOMAIN` + `APP_BASE_URL`. On mismatch, `Auth0Client` threw `InvalidConfigurationError: Missing: domain` and every test timed out before running. Fixed by aligning the CI env names to v4. **E2E CI is now unblocked for the Student Flow project.**
